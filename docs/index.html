What it does

Consumer products generate millions of events (sessions, purchases, notifications, level-ups). Collecting it is easy — deciding what to do next, respecting business rules, and proving the decision worked, is the hard part. AttentionOS makes that loop explicit, measurable, and improvable.

The system, end to end

1
Behavior

Synthetic event generator — 15 event types, 8 user archetypes (whale, casual, at-risk, declining…), with irreducible return noise so behavior isn't perfectly predictable (which is why metrics are realistic, not 1.0).

src/data/generator.py
2
Feature Engineering

40 leakage-safe rolling-window features — recency, frequency, intensity, trend, diversity. Each feature uses only past data (strict reference-date cutoff before the label window).

src/features/engine.py
3
Prediction

Will the user return in 7 days? Will they purchase in 7 days? Three model families (Logistic · Random Forest · XGBoost) on a chronological 70/15/15 split; best selected on test ROC-AUC.

src/models/retention.py · monetization.py
4
Decision

A deterministic decision engine scores candidate actions by expected value minus cost, fatigue and risk; applies guardrails as hard constraints; may return NO_ACTION when confidence is low.

src/decision_engine/engine.py
5
Explanation

Every decision ships with a plain-language AI explanation (provider-agnostic LLM) plus a guaranteed deterministic fallback.

src/llm/explainer.py
6
Experimentation

Deterministic hash-based A/B assignment + Welch's t-test significance analysis — we measure whether the action actually worked and feed it back.

src/experiments/engine.py
7
Serving + Monitoring

FastAPI backend (9 endpoints) + Streamlit dashboard (5 pages) + decision/outcome tracking for auditability.

src/api/ · dashboard/ · src/monitoring/

Honest limitations

This is a portfolio demonstration, and I'm upfront about it:

  • Synthetic data — generated, not real users; the pipeline is designed so real event streams can be substituted without changing downstream code.
  • No true causal inference from models — predictions are correlational; only the experiment framework gives causal estimates.
  • Simulated treatment effects — experiment outcomes are simulated, not measured from real user responses.
  • Heuristic LTV — LTV uses a simple purchase-probability approximation, not formal survival/causal LTV.
